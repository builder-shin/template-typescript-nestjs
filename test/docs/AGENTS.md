# test/docs

## 목적

README의 구조 설명과 전체 검증 절이 실제 저장소 및 정해진 명령 목록과 일치하는지 검사한다.

## 주요 파일

| 파일             | 설명                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------- |
| `readme.spec.ts` | README의 검증 절과 명령 순서, 구조에 나열된 경로의 존재, ESM과 `.js` 설명을 검사한다. |

## AI 에이전트 지침

### 작업 시 주의사항

- 검증 명령 검색은 `## 검증`부터 다음 2단계 제목 전까지로 제한한다. 다른 절의 같은
  명령 때문에 순서 검사가 달라지도록 문서 전체 검색으로 바꾸지 않는다.
- `## 구조` 뒤의 `text` 코드 블록에서 각 줄의 첫 공백 구분 토큰을 경로로 해석한다.
  구조 표기 방식을 바꿀 때 이 파서와 README를 함께 검토한다.
- `VERIFICATION_COMMANDS`의 명령 문자열과 순서는 README 및 루트 AGENTS.md의
  전체 검증 절과 맞춘다. 명령 변경 없이 테스트를 통과시키려고 다른 절의 표기를 바꾸지 않는다.
- AGENTS.md 검사 추가를 예고한 주석은 있지만 현재 실행되는 검사는 README만 읽는다.
  이 테스트의 통과를 AGENTS.md 링크나 내용 검증으로 보고하지 않는다.

### 테스트 요구사항

저장소 루트에서 다음 명령을 실행한다.

```bash
pnpm test:quick --runInBand --runTestsByPath test/docs/readme.spec.ts
```

테스트 코드를 수정했다면 `pnpm typecheck`도 실행한다. 이 검사는 문서를 읽을 뿐,
README에 적힌 Docker나 셸 명령을 실행하지 않는다.

### 공통 패턴

- `import.meta.url` 기준으로 저장소 경로를 계산하고 문서를 UTF-8로 읽는다.
- 명령의 존재와 출현 순서를 별도로 단언한다.
- 구조 검사는 설명 문장 대신 실제 경로의 존재를 확인한다.

## 의존성

### 내부

저장소 루트의 `README.md`와 문서에 나열된 경로에 의존한다. 테스트 실행 규칙은
[상위 가이드](../AGENTS.md)를 따른다.

### 외부

Jest와 Node의 `fs`, `url` 모듈을 사용한다. 외부 서비스는 필요하지 않다.
