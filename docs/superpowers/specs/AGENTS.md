# specs

## 목적

NestJS 템플릿이 제공할 아키텍처와 공개 계약을 정의한다. 전체 설계에는 Phase 0부터 8까지의
목표가 포함된다. 현재 구현은 Phase 0이므로 JSON:API 협상·오류, ORM, CRUD, 인증과 작업 큐를
이미 제공하는 기능으로 설명하지 않는다.

## 작업 지침

- 한국어 본문, 날짜, 표, 코드 블록과 의도적 차이의 근거를 보존한다. 스택 표는 작성
  시점의 선택 기록이며 현재 설치 상태는 루트 패키지 설정과 잠금 파일에서 확인한다.
- 계약 변경 시 계층 소유권과 비목표를 함께 검토한다. 모델은 저장 구조, 스키마는 입력과
  조회 정책, 시리얼라이저는 공개 표현, 리소스 컨트롤러는 선언을 소유하도록 설계되어 있다.
- 명시적 라우트 등록, 실제 PostgreSQL 검증, 단일 검증 게이트와 한국어 문서군의 방향을
  유지한다. 아직 없는 계획 디렉터리와 의존성을 현재 구조로 소개하지 않는다.
- 전체 검증 명령은 README의 `## 검증`과 문자열·순서를 맞춘다. 설계 변경에 필요한
  계획·구현·테스트 후속 작업을 구분하고, 문서 변경을 구현 완료로 취급하지 않는다.
- `docs/`는 Prettier 제외 대상이다. 기록을 수정할 때 무관한 일괄 재포맷을 피한다.

## 확인 방법

형제 계획과의 상대 링크, Markdown 구조, 현재 기능과 예정 기능의 구분을 확인한다.
검증 명령 변경 시 저장소 루트에서 `pnpm test:quick --runInBand test/docs/readme.spec.ts`를
실행하고 README와 직접 대조한다. 현재 문서 테스트는 README를 검사하며 설계 문서나
AGENTS.md의 모든 문장을 검증하지 않는다. 문서만 정리할 때 후속 Phase의 코드를 만들지 않는다.
