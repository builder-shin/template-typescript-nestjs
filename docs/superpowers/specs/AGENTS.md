# specs

## 목적

NestJS 템플릿의 아키텍처와 공개 계약을 정한 설계를 보관한다. 전체 설계에는 Phase 0–8의
목표가, 계약 통일 설계에는 FastAPI 참조와의 드리프트 및 참조 자원 읽기 라우트가 담겨 있다.
작성 당시의 스택·현재/목표 표를 현재 구현으로 단정하지 않고 소스와 이후 룰링에 대조한다.

## 작업 지침

- 한국어 본문, 날짜, 표, 코드 블록과 의도적 차이의 근거를 보존한다. 스택 표는 작성
  시점의 선택 기록이며 현재 설치 상태는 루트 패키지 설정과 잠금 파일에서 확인한다.
- 계약 변경 시 계층 소유권과 비목표를 함께 검토한다. 모델은 저장 구조, 스키마는 입력과
  조회 정책, 시리얼라이저는 공개 표현, 리소스 컨트롤러는 선언을 소유하도록 설계되어 있다.
- 명시적 라우트 등록, 실제 PostgreSQL 검증, 단일 검증 게이트와 한국어 문서군의 방향을
  유지한다. 전체 설계의 파일 목록이나 라이브러리 선택이 실제와 다르면 해당 단계의
  룰링에서 근거를 찾는다. 예를 들어 Phase 7은 순수 BullMQ와 독립 워커를 선택했다.
- 전체 검증 명령은 README의 `## 검증`과 문자열·순서를 맞춘다. 설계 변경에 필요한
  계획·구현·테스트 후속 작업을 구분하고, 문서 변경을 구현 완료로 취급하지 않는다.
- `docs/`는 Prettier 제외 대상이다. 기록을 수정할 때 무관한 일괄 재포맷을 피한다.
